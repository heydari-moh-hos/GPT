# استراتژی محتوای بلوتل

## نگاشت قصد جست‌وجو به صفحه

| مسیر | عبارت اصلی | قصد و نقش محتوا |
| --- | --- | --- |
| `/` | تلفن ابری بلوتل | معرفی برند و هدایت به راهنما و مسیر مشاوره |
| `/cloud-telephony/` | تلفن ابری چیست | تعریف، پیش‌نیاز و کاربرد؛ قصد آموزشی |
| `/buy-cloud-phone/` | خرید تلفن ابری | ارزیابی خرید، ظرفیت و قرارداد؛ قصد تجاری |
| `/cloud-pbx/` | مرکز تلفن ابری، Cloud PBX | معماری، مسیریابی و کنترل دسترسی |
| `/features/` | امکانات تلفن ابری | ارزیابی قابلیت‌های رایج، با تفکیک مشخصات محصول |
| `/pricing/` | تعرفه تلفن ابری | اجزای هزینه؛ بدون قیمت ساختگی |
| `/solutions/` | تلفن ابری برای شرکت‌ها | سناریوهای فروش، پشتیبانی و شعب |
| `/about/` | درباره بلوتل | اعتماد و هویت برند؛ منتظر اطلاعات رسمی |
| `/contact/` | تماس با بلوتل | مسیر ارتباط؛ فعلاً فرم غیرفعال |
| `/blog/` | راهنمای تلفن ابری | کشف محتوای آموزشی و دسترسی به مقالات |

این نقشه مبتنی بر قصد جست‌وجو است، نه داده تأییدشده حجم جست‌وجو. پیش از اولویت‌بندی نهایی از Search Console و پژوهش رقبا استفاده شود. صفحات خرید و تعرفه پس از تأیید اطلاعات تجاری تکمیل شوند؛ به‌جای ساخت صفحات تکراری برای هر مترادف، محتوای همان صفحه توسعه یابد.

## برنامه محتوای پیشنهادی

۱. مقایسه مدل ابری و سانترال محلی، کیفیت اینترنت و چک‌لیست خرید: سه مقاله اولیه موجود؛ لینک به صفحه تعریف، خرید و تعرفه.
۲. طراحی مسیر تماس در ساعات کاری و خارج از ساعات کاری: مثال عملی بدون نسبت دادن قابلیت تأییدنشده به محصول؛ لینک به Cloud PBX.
۳. تعداد داخلی در برابر تماس هم‌زمان: مثال محاسباتی با فرض‌های صریح؛ لینک به خرید و هزینه‌ها.
۴. امنیت و نگهداری ضبط مکالمه: دسترسی، حذف و سیاست سازمان؛ نیازمند بازبینی حقوقی قبل از ادعای قانونی.
۵. برنامه مهاجرت برای تیم چندشعبه‌ای: چک‌لیست آزمون، آموزش و مسیر برگشت؛ لینک به راهکارها.
۶. مطالعه موردی فقط پس از رضایت مشتری و دریافت شواهد واقعی؛ هیچ مطالعه موردی فرضی با ظاهر واقعی منتشر نشود.

برای هر مطلب یک مسئله مشخص، مثال قابل استفاده، نویسنده تأییدشده در صورت وجود، تاریخ واقعی انتشار و بازبینی و پیوند به اقدام بعدی تعیین شود. تاریخ و نویسنده در نسخه اولیه جعل نشده‌اند. از صفحات شهری انبوه و بازنویسی کم‌ارزش مقالات پرهیز شود.

## چک‌لیست فنی

- [x] HTML استاتیک برای همه مسیرهای اصلی و مقالات؛ `output: export` و static params.
- [x] عنوان و توضیح اختصاصی، canonical با HTTPS و trailing slash هماهنگ.
- [x] sitemap و robots استاتیک؛ بدون مسیرهای ۴۰۴ در sitemap.
- [x] Open Graph، Twitter، تصویر محلی با اندازه مشخص و آیکون برند.
- [x] Organization فقط با نام و دامنه معلوم؛ BreadcrumbList و Article بر مبنای محتوای موجود.
- [x] یک H1 در هر صفحه محتوایی، H2های ساختاری و لینک‌های داخلی واقعی.
- [x] زبان فارسی و RTL، منوی موبایل قابل استفاده با صفحه‌کلید و skip link.
- [x] فونت محلی WOFF2، وزن محدود، font-display swap و تصویر hero بدون دانلود عکس سنگین.
- [x] فرم نمایشی غیرفعال؛ بدون tracker، درخواست ثبت داده یا Backend.
- [ ] بازبینی مشخصات تجاری، اطلاعات حقوقی و محتوای برند پیش از انتشار عمومی.
- [ ] تست شبکه HTTPS، ریدایرکت www و slash، headerها و صفحه ۴۰۴ در Cloudflare.
- [ ] بررسی Rich Results Test و Schema Validator روی URL نهایی؛ Article و Breadcrumb به‌تنهایی تضمین نمایش rich result نیستند.
- [ ] ثبت Domain property و sitemap در Google Search Console پس از تأیید مالک.
- [ ] تست Lighthouse روی موبایل و اندازه‌گیری LCP، INP و CLS؛ سپس پایش داده میدانی.
- [ ] کنترل دسترسی preview و حذف مانع ایندکس فقط هنگام انتشار رسمی.

معیارهای پیشنهادی پس از انتشار: تعداد صفحات معتبر ایندکس‌شده، نمایش و کلیک غیرنام‌برند، نرخ کلیک هر صفحه و عملکرد موبایل. تبدیل به درخواست مشاوره تنها پس از فعال‌شدن مسیر امن قابل سنجش است. هدف عددی بدون خط مبنا تعیین نشده است.
