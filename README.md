# بلوتل | BulutTel

وب‌سایت معرفی فارسی، RTL و Mobile First برای https://buluttel.ir. پیاده‌سازی با Next.js App Router، TypeScript، Tailwind CSS و خروجی استاتیک. نسخه نخست فاقد Backend، ثبت‌نام، پنل و سیستم تماس است.

## اجرا

Node.js 24 و npm 11 در محیط توسعه فعلی استفاده شده‌اند. برای Cloudflare نیز Node 24 انتخاب کنید.

```sh
npm ci
npm run dev
npm run typecheck
npm run build
npm run check:static
npm run preview
```

اگر مسیر cache پیش‌فرض قابل نوشتن نیست: `npm ci --cache /tmp/buluttel-npm-cache`.
`build` تمام صفحات را داخل `out/` می‌سازد. `preview` تنها برای بررسی محلی است؛ سرویس دائمی در انتشار لازم نیست.

## ساختار

- `src/app`: صفحه اصلی، صفحات محتوایی با مسیر `[slug]`، مجله و مقالات؛ metadata، sitemap و robots.
- `src/components`: سربرگ با منوی موبایل، پابرگ، قالب محتوا و فرم نمایشی.
- `src/lib/content.ts`: محتوای اصلی، اطلاعات برند و مقالات قابل ویرایش؛ داده‌های تجاری تأییدنشده با عبارت «در انتظار تأیید» مشخص شده‌اند.
- `src/lib/seo.tsx`: canonical، metadata شبکه‌های اجتماعی و JSON-LD امن.
- `public`: آیکون، تصویر اشتراک‌گذاری محلی و تنظیمات کش و امنیت.
- `docs/seo-strategy.md`: نقشه کلیدواژه و برنامه محتوا و چک‌لیست پیش از انتشار.
- `scripts/check-static.mjs`: کنترل HTML خروجی، SEO، مسیرها، لینک‌ها و عدم ارسال فرم.

فونت Vazirmatn از بسته محلی و با وزن‌های ۴۰۰، ۵۰۰ و ۷۰۰ بارگذاری می‌شود؛ درخواست فونت به سرویس ثالث ارسال نمی‌شود. تصویر مفهومی اصلی با CSS و SVG ساخته شده و اسکرین‌شات واقعی محصول نیست. منوی موبایل، انتخاب سناریوی مفهومی و reveal سبک از JavaScript سمت کاربر استفاده می‌کنند؛ متن اصلی صفحات در HTML استاتیک موجود است و با JavaScript غیرفعال هم دیده می‌شود.

## انتشار روی Cloudflare Pages

۱. شاخه `feat/buluttel-website` را در GitHub push و برای بررسی Pull Request ایجاد کنید. مخزن فعلی ابتدا خالی بوده و شاخه اصلی هنوز commit ندارد؛ پیش از PR باید یک شاخه پایه توسط مالک مخزن ایجاد شود. ادغام باید پس از تأیید مالک انجام شود.
۲. در Cloudflare، Workers & Pages → Create application → Pages → Connect to Git را انتخاب کنید و دسترسی به همین مخزن GitHub بدهید.
۳. شاخه انتشار را طبق تصمیم مالک انتخاب کنید. برای بررسی این نسخه می‌توان پروژه آزمایشی را به شاخه feature متصل کرد. تنظیمات: Build command = `npm run build`، Build output directory = `out`، Root directory = ریشه مخزن، Environment variable = `NODE_VERSION=24`. نیازی به adapter، Functions یا `next start` نیست. اگر preset مقدار دیگری برای خروجی قرار داد، آن را به `out` تغییر دهید.
۴. هر push به شاخه production باعث build و انتشار خودکار می‌شود. برای سایر شاخه‌ها Preview deployments را فعال کنید. روی دامنه آزمایشی Pages قابلیت «Enable access policy» را فعال کنید تا نسخه‌های قبل از تأیید عمومی و ایندکس نشوند؛ صرف canonical جایگزین کنترل دسترسی نیست. robots نسخه production اجازه ایندکس می‌دهد.
۵. پس از انتشار، مسیرهای فارسی‌محتوا و URLهای انگلیسی پایدار، `/sitemap.xml`، `/robots.txt`، صفحه ۴۰۴ و منابع فونت را بررسی کنید. خروجی آزمون فایل‌ها جای آزمون شبکه Cloudflare را نمی‌گیرد.

### دامنه و DNS (راهنما؛ هیچ تغییری انجام نشده)

در پروژه Pages، Custom domains → Set up a custom domain را انتخاب و `buluttel.ir` را اضافه کنید. برای apex، دامنه باید به‌عنوان zone در همان حساب Cloudflare فعال باشد؛ در صورت نیاز nameserverهای اعلام‌شده Cloudflare را در ثبت‌کننده دامنه وارد کنید. پیش از تغییر، از تمام رکوردهای DNS نسخه پشتیبان بگیرید و رکوردهای ایمیل MX/TXT و سرویس‌های موجود را حفظ کنید. از مقادیر واقعی نشان‌داده‌شده در Cloudflare استفاده کنید؛ مقدار DNS حدسی وارد نکنید.

برای `www.buluttel.ir` نیز ابتدا آن را در Custom domains ثبت کنید و سپس CNAME تأییدشده را طبق پنل اضافه کنید. Redirect Rule برای هدایت ۳۰۱ نسخه www به `https://buluttel.ir` و حفظ مسیر و query ایجاد کنید. HTTPS و صدور گواهی را پس از فعال‌شدن DNS بررسی کنید. هیچ API یا رکورد DNS از این پروژه تغییر داده نمی‌شود.

### پیش از عمومی شدن

اطلاعات حقوقی، راه تماس، امکانات قطعی و تعرفه‌ها باید توسط مسئول برند تأیید شوند. فرم در این نسخه disabled است و داده‌ای جمع‌آوری نمی‌کند. فعال‌سازی نیازمند مقصد امن، اطلاعیه حریم خصوصی، کنترل ضداسپم و بررسی مستقل است و در دامنه این فاز نیست. از درج نظر مشتری، رتبه، قیمت و سابقه ساختگی خودداری کنید.

در Search Console یک Domain property برای `buluttel.ir` بسازید؛ TXT دقیق ارائه‌شده گوگل را با تأیید مالک در DNS اضافه کنید و sitemap را ثبت کنید. قبل از انجام این کار کد تأیید حدسی در سایت درج نکنید.

## وضعیت بررسی

نتایج build، TypeScript و بررسی خروجی در گزارش تحویل ثبت می‌شوند. اندازه‌گیری واقعی Core Web Vitals به سایت منتشرشده، Lighthouse و داده میدانی نیاز دارد؛ هیچ امتیاز یا رتبه تضمینی ادعا نمی‌شود. تغییرات فقط در شاخه feature آماده شده‌اند و merge یا انتشار عمومی خودکار انجام نشده است.

## بازطراحی بصری

هویت جدید و اجزای نمای مفهومی محصول در [گزارش بازطراحی](docs/visual-redesign.md) توضیح داده شده‌اند. شاخه بازطراحی `feat/buluttel-visual-redesign` است؛ نسخه اولیه در شاخه قبلی و commit `c47313a` محفوظ است. صفحات داخلی نیز تایپوگرافی و رنگ‌بندی هماهنگ دارند. برای بررسی بازطراحی، شاخه جدید را به Preview deployment متصل کنید و تنها پس از تأیید ادغام کنید.
